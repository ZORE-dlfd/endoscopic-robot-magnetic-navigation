# 肛门入口方向修复

## 错误与原因

上一版实际从肠道深部端开始进镜，和原版已确认的肛门入口相反。不是患者摆位或观看角度的问题。生成器直接读取了旧 `数据/仿真输入/trajectory_state.csv`，其坐标顺序与原版 `source` 完全相反；控制用旧 CSV，显示和相机参考用原版 source，造成了方向不一致。上一轮仅验证“走完全程”和刚体变换，没有把进镜起点与肛门入口做对应核验，这是漏检。

原版未旋转坐标中的肛门入口为 `(0.970171, -145.567, -506.25)` mm，深部终点为 `(35.5332, -257.172, -342.2)` mm。横卧后分别为 `(-16.500845, 189.817165, 161.341661)` mm 和 `(18.062184, 25.767165, 49.736661)` mm。上一版的实际起点距正确入口约 201.402 mm。

## 修复原则

1. 进镜路线只取原版已确认的 source；路线坐标、弧长、风险、速度约束和机身参考朝向统一，旧反序 CSV 不再用于磁驱动生成。
2. 进镜固定为“肛门入口 → 肠道深部”，退镜固定为“肠道深部 → 同一个肛门入口”。不倒放旧视频，不换标签冒充修复。
3. `数据/仿真输入/route_direction.json` 固定原始入口、深部坐标和允许误差；生成前检查原版路线是否匹配，方向不符直接拒绝。
4. 生成后核验实际起点、进镜终点、退镜起点和退镜终点，且换向继承完整机身状态。程序加载时再次核验实际三阶段端点和入口处向内的机身朝向。
5. 重新积分八线圈磁驱动、重新执行原密集搜索与短时预测，并重新评价进退镜覆盖。仰卧摆放、世界 −Z 重力、只减速不等待及原 UI 布局保留。
6. 界面明确标为“肛门入口 · 开始进镜”“肠道深部 · 开始退镜”“回到肛门入口”，三维图增加绿色入口、紫色深部标记。
